# 法人籌碼五票 × 個股 K 線疊圖

2026/08 三檔個股（2330 台積電、2308 台達電、2368 金像電）日 K 線，
與自訂的「法人籌碼五票」分數疊在同一張圖上。

## 怎麼打開

**最簡單**：直接用瀏覽器打開 `index.html`（雙擊即可）。
頁面會先嘗試讀 `data/prices.json` 與 `data/chips.csv`；用 `file://` 直開時
瀏覽器會擋掉這種讀取，此時會自動改用 `data/prices.js` / `data/chips.js`
這兩支同樣內容的備援檔（`<script>` 載入不受限制），畫面完全一樣。

**想要乾淨一點**：在資料夾裡跑

```bash
python3 -m http.server 8000
# 然後開 http://localhost:8000/
```

ECharts 由 CDN 載入，所以開啟時需要網路。要完全離線的話，把
`echarts.min.js` 下載到同一層，並改掉 `index.html` 裡那行 `<script src=...>`。

## 檔案

```
index.html          畫面結構
app.js              計分、圖表、表格（所有計算都在瀏覽器端即時做）
style.css           樣式
fetch_prices.py     抓證交所股價，產生 data/prices.json（+ .js 備援）
build_artifact.py   把上面全部打包成 dist/single.html 單一檔案
tests/verify.py     驗證腳本：Python 獨立算一次分數，和頁面實際渲染結果逐格比對
data/chips.csv      籌碼五欄原始資料（手動維護）
data/prices.json    股價（fetch_prices.py 產生）
data/raw/           證交所 API 的原始回應，保留供稽核
```

## 換成 9 月的資料

1. **更新籌碼**：把 9 月的五個欄位貼進 `data/chips.csv`（格式不變，日期用
   `2026/09/01` 這種西元格式）。這份是手動維護的，程式不會去抓。

2. **抓股價**：

   ```bash
   python3 fetch_prices.py --month 202609
   ```

   會對每檔股票各打一次證交所 API，原始回應存到 `data/raw/`，
   然後重新產生 `data/prices.json`、`data/prices.js`、`data/chips.js`。
   若任何一檔抓不到（連線失敗、`stat` 非 OK、`data` 為空），
   腳本會**直接中止並印出錯誤，不會寫出 prices.json、也不會用估計值補值**。

   跑完最後會自動檢查交易日：三檔之間是否一致、以及和 `chips.csv` 是否對得上，
   對不上會把是哪幾天印出來。

   換股票用 `--stocks 2330,2454,3661`。

3. **改結算日**：打開 `app.js`，最上面

   ```js
   var SETTLEMENT = ['2026/08/19'];
   ```

   換成 9 月的結算日（通常是第三個星期三）。可以放多個日期。

4. 重新整理頁面即可。

## 五票規則

| 票 | 欄位 | 判斷 |
|---|---|---|
| 1 | `foreign_fut` 外資台指期未平倉 | `> 門檻` → +1，否則 -1（門檻預設 -83000，可調） |
| 2 | `top10_trader` 前十大交易人 | `> 0` → +1，否則 -1 |
| 3 | `top10_specific` 前十大特定人 | `> 0` → +1，否則 -1 |
| 4 | `foreign_opt` 選擇權外資 | `> 0` → +1，否則 -1 |
| 5 | `dealer_opt` 選擇權自營商 | `> 0` → +1，否則 -1 |

期貨小計 = 票 1+2+3，選擇權小計 = 票 4+5，總分 = 五票相加（-5 ~ +5）。

門檻改成任何值，圖表、統計卡、表格都會即時重算，不會重新整理頁面。
控制列右邊那行文字會一直顯示 **-83000 與 -80000 兩個門檻判讀不同的是哪幾天**。

### 本日操作

表格與 tooltip 在「口數」和「票」之間各多一欄 **本日操作**＝今日口數 − 昨日口數，
正數紅、負數綠。第一個交易日沒有前一日可比，顯示 `—`（不用 0 代替，
0 代表「持平」，和「沒資料」不是同一件事）。

### 副圖的雙軸對齊

`foreign_fut` 量級約 -9 萬、其他四項是數千，必須用獨立右軸。
兩軸如果各自 auto-scale，「外資有沒有站上門檻」和「其他項是不是正的」
會落在畫面上不同的高度，讀起來對不起來。

所以兩軸都固定切成 4 段，並讓**右軸的門檻和左軸的 0 落在同一條格線上**，
格線因此完全重疊，那條線以上就是投 +1、以下就是 -1，五條線讀法一致。
門檻一改、或籌碼線的勾選一變，兩軸會一起重算（刻度仍維持整數）。例如：

```
門檻 -83000 → 左軸 -12000 -6000 0 6000 12000
              右軸 -91000 -87000 -83000 -79000 -75000
門檻 -80000 → 左軸 -12000 -6000 0 6000 12000
              右軸 -92000 -86000 -80000 -74000 -68000
```

## 資料口徑（重要）

- `foreign_fut` 是**純大台（TX）**口徑。
- `top10_trader` / `top10_specific` 是期交所 **`TX + MTX/4 + TMF/20` 所有契約合併**
  口徑（小台、微台已換算併入）。

兩者口徑不同，本頁只各自獨立呈現與投票，**沒有做任何相加減**。

停牌或無交易的日子，K 棒留空，不用前一日補值。

# 法人籌碼五票 × 個股 K 線疊圖

三檔個股（2330 台積電、2308 台達電、2368 金像電）的日 K 線，和自訂的
「法人籌碼五票」分數疊在同一張圖上，資料每個交易日自動更新。

## 怎麼打開

直接用瀏覽器打開 `index.html`（雙擊即可）。頁面會先讀 `data/site.json`；
用 `file://` 直開時瀏覽器會擋掉這種讀取，此時自動改用同內容的 `data/site.js`。
想乾淨一點就 `python3 -m http.server 8000`。

ECharts 由 CDN 載入（cdnjs，失敗自動改用 jsdelivr），所以開啟時需要網路。

## 資料從哪來

五個籌碼欄位**全部來自期交所**，沒有手動步驟、沒有二手來源：

| 欄位 | 來源 | 取值 |
|---|---|---|
| `foreign_fut` | 三大法人-區分各期貨契約 | 臺股期貨 → 外資 → 未平倉多空淨額（口數） |
| `top10_trader` | 期貨大額交易人未沖銷部位 | TX / 到期月份 999999 / 交易人類別 0 → 前十大買方 − 賣方 |
| `top10_specific` | 同上 | 同上，交易人類別 1 |
| `foreign_opt` | 三大法人-區分各選擇權契約 | 臺指選擇權 外資：買權未平倉淨額 − 賣權未平倉淨額 |
| `dealer_opt` | 同上 | 同上，自營商 |

股價來自證交所 `STOCK_DAY`（一次回一整月）。

口徑說明：`foreign_fut` 是純大台（TX）；`top10_*` 是 `TX+MTX/4+TMF/20` 合併口徑
——期交所在 `TX` 這個代碼底下公布的就已經是合併值（CSV 的商品名稱欄直接寫著），
不需要自己加權。兩者口徑不同，本頁只各自獨立呈現與投票，**不做相加減**。

## 每日更新

```bash
python3 update_daily.py                        # 今天（台北時間）
python3 update_daily.py --date 2026/09/08      # 指定某天
python3 update_daily.py --days 120             # 回填最近 120 天（≒ 四個月）
python3 update_daily.py --from 2026/06/01      # 從某天到今天
python3 update_daily.py --from 2026/06/01 --to 2026/07/31
python3 update_daily.py --dry-run              # 只抓不寫
```

離開碼：`0` 正常（含「今天還沒有資料」）、`1` 抓取或解析失敗、
`2` 太久沒有新資料（`--max-stale-days` 觸發）。

### 幾個刻意的設計

**不看時鐘，只看資料。** 每個來源回傳的內容都帶自己的日期，對不上就當作尚未公布，
安靜結束、不寫檔、不算失敗。實測非交易日與未來日期都回 0 筆資料，不會給前一日的數字。
因此**不需要維護台股行事曆**。

**五欄同進退。** 任何一項缺了，當天完全不寫入。寧可隔天補抓，也不要留下半套資料。

**冪等。** 已存在的日期預設跳過（`--force` 才覆寫），補跑 / 手動觸發 / 兩個排程重疊都安全。

**解析不到就報錯，不回 0。** 期交所是 HTML 表格，改版遲早會壞。找不到
「臺股期貨 → 外資」那一列時流程直接失敗——默默寫個 0 進歷史檔，那種錯誤要幾個月後才會發現。

**HTTP 200 不等於成功。** 期交所的 CSV 下載端點少帶一個表單欄位會回 200 加一頁錯誤 HTML，
所以要檢查回應開頭是不是預期的表頭。（註：HTML 查詢頁的回應**一定**含 `alert(` 字樣，
成功時也有，那是版型的 noscript 樣板，不能拿來當失敗訊號。）

**取數依據留檔。** 每天把實際用來算那五個數字的那幾列存進 `data/raw/chips/`（約 2 KB／天）。
完整 HTML 一天約 1 MB，一年幾百 MB 不值得留；只留這幾列，回頭查證某天的數字就夠了。

## GitHub Actions

`.github/workflows/daily.yml` 目前**只開手動觸發**。

先到 Actions 頁按一次 Run workflow（`days` 預設 120，等於一次回填約四個月），
確認 GitHub 的海外 IP 沒有被證交所／期交所擋掉。
確認可行之後，把 workflow 裡 `schedule:` 那段取消註解即可（16:00 主跑、18:00 補跑，UTC 是 8 點與 10 點）。

真的被擋，就改在 Mac 上用 launchd 排程跑同一支 `update_daily.py`，腳本一行都不用改。

## 檔案

```
index.html / app.js / style.css   前端（只讀 data/site.json）
config.json                       股票清單、均線天數、門檻預設、區間選項
taifex.py                         期交所抓取與解析
fetch_prices.py                   證交所股價抓取
store.py                          append-only 歷史檔讀寫（原子寫入、冪等）
build_site.py                     歷史檔 → data/site.json（結算日自動推算）
update_daily.py                   每日流程：抓取 → 驗證閘門 → append → build
build_artifact.py                 打包成 dist/single.html 單一檔案
data/history/chips.csv            六欄，append-only，全部歷史
data/history/prices.csv           date,code,open,high,low,close,change,volume
data/raw/                         證交所原始回應 + 每日取數依據
tests/                            見下
```

歷史檔用 CSV 是因為每天只 append 一行，`git diff` 一眼看得出當天抓到什麼。
一年約 240 個交易日、三檔股票約 720 行，十年也還是小檔案。

`site.json` 放的是**全部歷史**而不是只有視窗內的資料，這樣區間切換能立刻切，
MA20 也自然有暖身資料，不必額外維護一份 warmup。

## 測試

```bash
python3 tests/test_taifex.py        # 期交所解析器（fixture 是 07/13、08/19、08/31 的真實回應）
python3 tests/test_update_daily.py  # 每日流程的行為（冪等、五欄同進退、失敗不寫檔）
python3 tests/verify.py             # 前端：用 headless 瀏覽器開實際頁面逐格比對
```

`test_taifex.py` 的期望值就是專案原本手工維護的 `chips.csv`——期交所改版時，
是測試先紅，而不是等資料已經寫髒了才發現。

其中 2026/07/13 這組 fixture 特別重要：期交所的期貨表格最後有一個
**「期貨小計」**區塊（所有期貨契約的加總，前綴只有 1 格而不是「序號＋商品名稱」）。
那一列的外資淨額是 -561,385，如果誤抓，數字看起來仍然像回事，但整個判讀都會錯。
測試會明確斷言取到的是臺股期貨的 -81,066。

`verify.py` 會用 Python 獨立重算一次五票分數、MA20 與乖離率，再把實際渲染出來的
表格與圖表設定逐格比對，另外還驗副圖雙軸對齊、深色主題下的表單對比度、區間切換。

## 五票規則

| 票 | 欄位 | 判斷 |
|---|---|---|
| 1 | `foreign_fut` | `> 門檻` → +1，否則 -1（門檻預設 -83000，可即時調整） |
| 2 | `top10_trader` | `> 0` → +1，否則 -1 |
| 3 | `top10_specific` | `> 0` → +1，否則 -1 |
| 4 | `foreign_opt` | `> 0` → +1，否則 -1 |
| 5 | `dealer_opt` | `> 0` → +1，否則 -1 |

期貨小計 = 票 1+2+3，選擇權小計 = 票 4+5，總分 = 五票相加（-5 ~ +5）。
控制列會一直顯示兩個預設門檻判讀不同的是哪幾天。

**本日操作**＝今日口數 − 昨日口數，比較對象是歷史上的前一個交易日，
所以切成最近 20 日時第一列照樣算得出來。第一個交易日顯示 `—`（不是 0）。

**乖離率**＝`(收盤 − MA20) / MA20 × 100%`，三檔都算，hover 一次列出。
正乖離 > 15% 標紅。均線只用有交易的日子算，暖身不足時顯示 `—`。

**逐日明細表格由新到舊**（最新的在最上面），但圖表維持時間軸方向（左舊右新）——
兩者刻意不一致：表格是拿來查最近幾天的，圖表是看趨勢的。
